# M0.6 — Supabase client setup

**Status:** Completed

**Est:** 2 hrs
**Tracking:** [Issue #26](https://github.com/storenode/tallythreads-web/issues/26)

## What this is

TallyThreads's backend is Supabase (Postgres + Auth + Storage), per the project
constitution (`specs/constitution.md`, §4). Before this task, `@supabase/supabase-js`
was installed as a dependency (from M0) but nothing in the app actually used it — there
was no configured client, and no tooling to manage the database schema.

This task wires up the **connection only**: a Supabase project to develop against, the
environment variables the app needs to reach it, a single shared client the rest of the
app can import, a CLI for schema migrations, and a script any developer can run to
prove their own `.env.local` is actually correct. It does not create any database
tables, authentication flow, or row-level security policies — that's module M1
(Constitution §5), which builds on top of this.

## Scope

**Included:**
- Supabase CLI installed as a dev dependency (`supabase`), for future schema
  migrations and type generation against the project — this does **not** run a local
  Docker Supabase stack; see "Remote-only, by design" below
- A single shared Supabase client (`src/lib/supabaseClient.ts`) that reads the project
  URL and anon key from environment variables and throws a clear error if either is
  missing, instead of failing silently or crashing somewhere unrelated later
- `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` typed in `src/vite-env.d.ts` so
  autocomplete and type-checking work on `import.meta.env`
- Step-by-step instructions (below) for where a developer gets their own project's
  URL and anon key
- A `pnpm supabase:check` script that makes a real network call to the configured
  project and fails clearly if it's unreachable or still set to the placeholder value

**Explicitly not included (deferred to M1):**
- Any database tables, migrations, or schema at all
- Row-level security (store-level data isolation)
- Authentication (phone OTP or Google Sign-In) — the client here is unauthenticated;
  no sign-in flow uses it yet
- Any UI that reads or writes Supabase data

## Remote-only, by design

Per the founder's instruction, local development connects directly to a **remote**
Supabase project rather than running Supabase's local Docker stack (`supabase start`).
That means:
- The Supabase CLI is used for project-level commands (`supabase link`, migrations,
  type generation) against the remote project, not for spinning up local Postgres
- Everyone working on this repo needs their own `.env.local` pointed at that same
  remote project (or their own, if projects diverge later) — there's no "just works
  out of the box" local database

## Setting up `.env.local`

`.env.local` is git-ignored and never committed — every developer creates their own.

1. Copy the template: `cp .env.example .env.local`
2. Get the two values from the Supabase dashboard:
   - Go to **[supabase.com/dashboard](https://supabase.com/dashboard)** and open the
     project (ask a teammate for an invite, or for the project URL, if you don't have
     access yet — there's no self-serve way to discover which project this is)
   - **Project Settings** (gear icon, bottom of the left sidebar) → **API**
   - Copy **Project URL** → paste as `VITE_SUPABASE_URL`
   - Under **Project API keys**, copy the key labeled **`anon` `public`** → paste as
     `VITE_SUPABASE_ANON_KEY`
   - Do **not** copy the `service_role` key into this file — see the warning below
3. Verify it actually works: `pnpm supabase:check`
   - Success looks like: `Supabase connection OK — https://<your-project>.supabase.co`
   - If it fails, the error message says why (missing var, still the placeholder
     value, or the project rejected the request — usually a copy-paste mistake)

Only the **anon** key ever goes in a `VITE_`-prefixed variable — everything prefixed
`VITE_` is compiled into the client bundle and is publicly visible to anyone using the
app. The service-role key must never appear in this repo; it belongs in Supabase Edge
Function secrets only (Constitution, M0 setup guide §11).

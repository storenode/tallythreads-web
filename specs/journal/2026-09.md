## 2026-09-05 — Purchase-Trip (M4) Phase 1 IMPLEMENTED & committed (session wrap-up)

> Read this first if you're a fresh chat picking up Purchase-Trip. It's the authoritative
> "where it stands" entry; the design-decision entries below give the reasoning trail.

**Status:** Phase 1 done, all green (typecheck clean, **34 unit tests pass**, 0 lint errors),
**committed as `37504f2`** on branch **`docs/specs-restructure-live-schema`** (rename to
`feat/m4-purchase-trips` before a PR, or squash-merge to `main`). Migrations were **applied to
the live Supabase DB** (`gmmeaplomgotqtivevkg`) and verified.

**What Purchase-Trip is:** the module a store owner uses for a buying trip — plan it (route,
budgets, forecast), then record actuals (supplier invoices, expenses) → true **landed cost**
per item + suggested **MRP**. Org-type independent (attaches to the *sourcing* org: independent
owner, chain buyer, or Bandrip Corporate; a franchise *branch* receives goods, doesn't source).
Full spec: `../roadmap/purchase-trips.md` (v0.3.3). Constitution: v1.12.0 (§5 reorder + §8).

**Key architectural decision (Option B):** built **offline-first with Dexie + a real sync
loop**, and that sync loop **is M2's core, built through Purchase-Trip as its first consumer**
(not online-first, not a separate 62h M2 first). Honors §2.I (offline-first) and lets §7's
sync-round-trip DoD be proven against a real feature. Constitution §5 was amended for this.

**Where the code lives:**
- **DB (live):** migrations `supabase/migrations/20260905000000_m4_purchase_trips.sql`
  (4 tables + RLS on `trip.create`/`trip.read`) and `20260905010000_m4_incoming_stock_visibility.sql`
  (price-free `incoming_stock` view + `trip.view_incoming` permission + `has_incoming_visibility()`).
  Tables: `purchase_trips`, `purchase_invoices`, `purchase_invoice_items`, `trip_expenses`
  (all integer paise, soft-delete, `last_modified_at`). Columns in `../reference/schema.md` §3A.
- **Offline layer:** `src/db/{purchaseTrips,purchaseInvoices,purchaseInvoiceItems,tripExpenses}.ts`
  (Dexie types, `db.version(6)`); `src/features/purchaseTrips/data/*` (write-through helpers,
  outbox enqueue); `src/sync/*` (the push/pull sync worker — pre-existing, drives all tables).
  **Important fix:** `createRow` client-generates the row `id` (uuid) at insert, so an
  offline-created invoice can reference its offline-created trip (no local→server id remap).
- **Money engines (pure, TDD, `src/lib/`):** `landedCost.ts` (expenses distributed by value,
  largest-remainder so shares reconcile exactly), `purchaseMargin.ts` (hybrid recipe/plugin —
  flat vs trending, whitelist plugin, never `eval`), `tripForecast.ts` (investment/revenue/
  profit; break-even is deferred → `backlog.md`), `mapsUrl.ts` (free keyless Google Maps
  verify-link), `money.ts` (₹↔paise). Each has a `.test.ts`.
- **UI (`src/features/purchaseTrips/`):** `pages/PurchaseTripsListPage` (list, sync badges),
  `pages/PurchaseTripCreatePage` (plan: multi-leg route + budgets + live forecast + Cart/Wallet),
  `pages/PurchaseTripDetailPage` (invoices/items/expenses + live landed-cost/MRP table + summary
  + planned-vs-actual + route edit), `components/RouteLegsTable`, `components/CartWalletSummary`,
  `legs.ts`. Routes registered in `src/features/stores/router.tsx` under `/org/:orgId/purchase-trips`.
  Store-facing price-free view: `src/features/operations/pages/IncomingStockPage.tsx` at
  `/ops/:storeId/incoming`.

**Route leg shape (jsonb, no migration to change):**
`{from, to, boarding, drop_point, distance_km (required), mode, price_paise, planned_purchase_paise}`.
Each leg shows a generated free "Verify on map ↗" link (human typo-detection, no API/key).
Trip-level **Cart** (Σ leg purchases, vs budget) + **Cash-to-carry Wallet** (cart + expenses)
readout sits in the plan card header (borderless/muted). *(Note: the founder manually merged
the create page's "Plan" and "Route" into one card — that file is the source of truth.)*

**Visibility split (security, not UI-hiding):** org_owner/org_manager see full financials via
`trip.read`; store staff read the **price-free `incoming_stock` view** (no cost/MRP/margin/
budget columns exist in it) gated by `trip.view_incoming` — enforced server-side.

**What is NOT built (deliberately):**
- **Phase 2 — Claude/Haiku AI budget estimator.** Needs its own **constitution §3/§8
  amendment** (AI: seeded→built), an `estimate-trip-budget` Deno Edge Function (Haiku,
  server-side key), a client "Estimate with AI" button, and the founder to set
  `ANTHROPIC_API_KEY` as a Supabase secret + a ~$5/mo spend cap. Not started.
- Break-even/ROI forecast, Places/Photon autocomplete, hotel discovery → `../roadmap/backlog.md`.
- Sync-cadence wiring (interval/foreground triggers + a "Sync now" button placement) — the
  worker exists (`src/sync/`); its trigger cadence isn't finalized (open).

**Immediate next step:** decide whether to start **Phase 2** (see prerequisites above) or
refine Phase 1. If Phase 2: write the §3/§8 amendment first, then the Edge Function + button;
founder sets the key/secret; test online; commit separately.

**Open questions:** sync cadence/interval; `suppliers` master timing; MRP→sales (M5) seam;
